Data model

Three containers carry everything. They are deliberately small: the package does not know where your data comes from, only what shape it arrives in.

The containers

Forecast is one ensemble at one lead time — a lead time and a vector of M member values:

Forecast(Hour(12), [291.2, 292.0, 290.4])

Member order is whatever the model delivered. Nothing depends on it except mean_abs_diff, which requires sorted input, so sorting happens once where it is needed rather than being imposed on the container.

InitForecast is all the lead times of one run, for one variable at one location: an initialisation timestamp, a vector of Forecasts in increasing lead time, and a corrected::Bool flag. The flag is what stops a corrected run being fed back into training or corrected twice — correct throws on a run that already carries it.

Observations is the verifying time series: strictly increasing UTC times and values of equal length. The constructor enforces both. Look values up with observation_at, which returns nothing rather than throwing when a time is not an observation time:

y = observation_at(obs, run.timestamp + Hour(12))
y === nothing && return          # not a training case, not an error

That nothing is deliberate. A forecast whose valid time has no observation is simply not a case, and both TrainingObject and the evaluation path skip it silently.

Getting ECMWF open data

download_ecmwf_ens fetches the perturbed members (type = pf) of surface parameters for one run and concatenates the GRIB messages into one file:

path = download_ecmwf_ens(Date(2026, 7, 14), "00", ("2t",), 0:3:24, "run.grib2";
                          members = 1:10, base_url = ECMWF_GCS_MIRROR)

It drives byte-range requests off the run's .index files, so it downloads only the messages asked for. The cost model is worth internalising: one message is one global field, about 0.6 MB, and you need one per member per step. Ten members over 3-hourly steps to +144 h is 490 messages, roughly 300 MB — for a single run.

Three roots are provided. ECMWF_OPEN_DATA is the live service, which keeps only the last few days. ECMWF_GCS_MIRROR is the Google mirror and has the archive back to February 2024 — use it for anything historical. ECMWF_AWS_MIRROR is the same archive but answers 503 SlowDown under load. Transient failures (throttling, and stalled transfers that never return an HTTP status at all) are retried with exponential backoff.

read_init_forecasts turns the file into one InitForecast per station, taking the nearest grid point with no interpolation:

run = read_init_forecasts(path, "t2m", [(39.13, -3.10)])[1]
init_time(run)      # not needed: run.timestamp already has it

The file must hold exactly one run, which is what download_ecmwf_ens writes. Each step's field block is read once and all stations are picked out of it, so asking for many stations at once is much cheaper than looping.

For a long archive, download each run to a temporary directory, extract the station values, and throw the GRIB away — examples/full_fit.jl does this and keeps only a few hundred kilobytes for 873 runs.

Bringing your own data

Nothing above is required. If you have forecasts from another model, build the containers directly:

runs = [InitForecast(t0, [Forecast(Hour(h), members(t0, h)) for h in 0:3:48], false)
        for t0 in init_times]
obs = Observations(station_times, station_values)

Everything downstream — training, correction, interpolation, evaluation — works on these types alone and never touches GRIB. Readers for specific data sources deliberately live outside the package; examples/siar.jl is one, for the Spanish SIAR station CSVs used throughout the examples.
